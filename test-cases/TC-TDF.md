# Test cases: Test Data Factory (TDF)

**Source of truth:** [user-stories/US-TDF.md](../user-stories/US-TDF.md)
**Application under test:** Test Data Factory 0.1.0, local dev server (`npm run dev`)
**Automation:** `tests/ui/`, `tests/a11y/` (Playwright). See "Automation candidates" below.
**Executed:** 2026-11-26, Chromium, by the Playwright suite (`npm run test:e2e`). US-TDF-0007 added and run in Phase 4 (version 0.2.0). Status reflects that run. Manual-only checks are marked Not Run until done by hand.

## AC gaps
1. **US-TDF-0001 AC1:** "Field N" uses the number of fields, so names can repeat after a removal (4 fields → remove one → add gives "Field 4", but a "Field 4" may already exist). Is a duplicate default name acceptable? **Needs confirmation.**
2. **US-TDF-0001 open question:** duplicate field names overwrite each other in JSON/Playwright exports. No AC says whether names must be unique. **Needs confirmation.**
3. **US-TDF-0002 AC2** defines boundaries for Text, Whole number and Date only. Email (64-character local part) and PH mobile (10/12 digits) boundaries exist in the tool but have no AC. Covered by unit tests; not covered here.
4. **US-TDF-0003 AC3:** marked (verify). Tested as written; result to be confirmed.
5. **US-TDF-0004 AC2:** "opens correctly in Excel" is manual-only and depends on the Excel version. Tested in one version; record which.
6. **US-TDF-0005 AC5** covers invalid JSON and an empty list, but not saved data that is valid JSON with the wrong content (e.g. an unknown field type or a missing name). **Missing rule;** included as a negative case in US-TDF-0005-TC-004 with the expected result assumed to match AC5.
7. **No AC** for what happens when browser storage is blocked (private mode, storage full). Low risk; not covered.
