# Defect Log

> Real bugs in Test Data Factory, found by testing it as an application under test.
> One row per defect, same format as the OrangeHRM project. Continue numbering from the last row.

**Summary:** 5 defects (0 Critical, 0 High, 3 Medium, 2 Low) · 5 fixed and retested
**How they were found:** all 5 by the Playwright suite on its first run (2026-11-26, Chromium). 2 of them by the **self-test**: data the tool exported for its own Min length input.

| Defect ID | Defect Title | Defect Description | Date Reported | Feature | Severity | Status | Category | Notes |
|---|---|---|---|---|---|---|---|---|
| DEF-001 | Email test data includes a domain that isn't reserved for testing | **Steps:** 1. Open the app (User signup preset). 2. Select the Email field. 3. Read the Valid rows. **Expected:** Every generated address uses example.com or a subdomain of it, which are reserved for testing (US-TDF-0002 AC9). **Actual:** "m.santos@mail.example.co.uk" is generated. example.co.uk is not reserved, so test data could reach a real mail server if used in a system that sends email. | 2026-11-26 | Generated values › Email | Medium | Closed | Functional | Found by US-TDF-0002-TC-007. Source: `src/lib/generators/email.ts`. The unit test only checked for the word "example", so it missed this. Fixed: now `m.santos@mail.example.com`; unit test tightened to require example.com. Retested by US-TDF-0002-TC-007 (now reads raw values from the JSON export, since the table shortens long addresses). |
| DEF-002 | Page goes blank when saved fields contain an unknown type | **Steps:** 1. Open the app. 2. In DevTools › Application › Local Storage, set `tdf.fields.v1` to `[{"id":"x","name":"Bad","type":"colour","required":true}]`. 3. Reload. **Expected:** The User signup preset loads, as it does for invalid JSON (US-TDF-0005 AC5, assumed for wrong-content JSON, see AC gap 6). **Actual:** The page is blank; the app crashes while rendering and the only way out is clearing storage. | 2026-11-26 | Saved fields | Medium | Closed | Error | Found by US-TDF-0005-TC-004c. Realistic cause: data saved by a future or older version with a different field type. The loader checks for an array but not the contents of each field. Fixed: the loader checks every saved field (`isFieldSpec`) and falls back to the preset if any is wrong. Retested by US-TDF-0005-TC-004a–c and 8 unit tests. |
| DEF-003 | Page scrolls sideways on a 375 px phone screen | **Steps:** 1. Open the app at 375 × 812. 2. Swipe left. **Expected:** No horizontal page scroll (US-TDF-0006 AC5). **Actual:** The page is 400 px wide; the Fields panel is 376 px in a 327 px column and pushes past the right edge. | 2026-11-26 | Layout (mobile) | Low | Closed | UI/Display | Found by US-TDF-0006-TC-003. The one-column grid uses `1fr`, which won't shrink below its content's minimum width. Fixed: `minmax(0, 1fr)` and `min-width: 0` on the panels. Retested by US-TDF-0006-TC-003. |
| DEF-004 | Min and Max accept scientific and hex notation as numbers | **Steps:** 1. Open the app. 2. Click + Add field. 3. Type `1e2` in Min length. 4. Then type `0x1A`. **Expected:** "Min must be a whole number" (US-TDF-0001 AC5). **Actual:** No error. `1e2` is used as 100 and `0x1A` as 26, so the generated data is based on limits the tester never meant. Same for Max and for whole number fields. | 2026-11-26 | Field builder › Min/Max | Medium | Closed | Functional | Found by the self-test US-TDF-0001-TC-005, using data the tool generated for itself ("Scientific notation: JavaScript reads it as 100"). Cause: the inputs are parsed with `Number()`. Fixed: Min/Max accept only plain digits with an optional minus (`parseLimit`); whole numbers must be safe integers. Retested by the self-test and 13 unit tests. |
| DEF-005 | Min length has no upper limit, unlike Max length | **Steps:** 1. Open the app. 2. Click + Add field. 3. Clear Max length. 4. Type `100001` in Min length. **Expected:** An error, as for Max length over 100,000 (US-TDF-0001 AC5). **Actual:** Accepted. The tool then builds boundary values of 100,001+ characters; `99999999999999999999` is also accepted. | 2026-11-26 | Field builder › Min length | Low | Closed | Functional | Found by the self-test US-TDF-0001-TC-005. **Needs confirmation:** AC5 only states the cap for Max. Developer decision: apply the same 100,000 cap to Min. Fixed: Min length over 100,000 shows "Min length is 100,000 characters at most". Retested by the self-test and a unit test. |
